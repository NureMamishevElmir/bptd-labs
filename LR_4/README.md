# ЛР 4. Алгоритм обміну ключами Діффі-Хеллмана

Мамішев Е. І., ПЗПІ-23-6, варіант 13. .NET 8.

## Проєкти
| Проєкт | Призначення |
|---|---|
| `Dh.Core` | власний `ModPow` (square-and-multiply), перевірка первісного кореня, тест Міллера-Рабіна, групи (Q=23/A=5 і RFC 3526 2048 біт), учасник `DhParty` (X, Y, K, відбиток) |
| `Dh.Cli` | консольна демонстрація: користувачі B, C, D, попарні ключі, атака MITM |
| `Dh.Web` | ASP.NET Core + SignalR: сервер-ретранслятор і чат у браузері (`wwwroot`) |
| `Dh.Tests` | xUnit-тести |

## Запуск
```
dotnet test                      # тести
dotnet run --project Dh.Cli      # демонстрація (--full — повні 2048-бітні числа)
dotnet run --project Dh.Web      # чат: http://localhost:5104
```
Відкрийте 3+ вкладки, у кожній введіть своє ім'я й ту саму кімнату.

## Параметри
* Навчальний режим: Q = 23, A = 5 (усі степені 5^k mod 23 різні — 5 є первісним коренем; 2 — ні).
* Надійний режим: 2048-бітне безпечне просте Q з RFC 3526 (група 14), Q = 2q+1.
  A — первісний корінь, якщо A^2 ≠ 1 і A^q ≠ 1 (mod Q). Найменший такий A = **11**
  (2, 3, 5, 7 породжують лише підгрупу порядку q).

## Протокол чату
1. Браузер генерує секретний X (`crypto.getRandomValues`) і обчислює Y = A^X mod Q власним `modPow` на BigInt.
2. `Join(room, name, mode, Y)` — сервер зберігає лише Y і розсилає кожному список інших учасників з їхніми Y.
3. Для кожної пари браузер обчислює K_ij = Y_j^X_i mod Q; ключ AES-256-GCM = SHA-256(K_ij).
   Відбиток (перші 8 hex SHA-256(K)) однаковий у двох вкладках — ключі збіглися.
4. Повідомлення шифрується окремо для кожного отримувача: `Send([{to, iv, ct}])`.
   Сервер пересилає кожному його шифротекст (`Message`) і показує у панелі «Що бачить сервер» лише base64.

Обрано попарне шифрування (а не груповий ключ), бо воно простіше: немає «власника кімнати»,
а новий учасник одразу отримує ключі з усіма іншими.

## Безпека і MITM
Стійкість спирається на складність дискретного логарифма: з Y, A, Q важко знайти X.
Але DH без автентифікації вразливий до атаки «людина посередині»: перемикач «Зловмисний сервер (MITM)»
змушує сервер підставляти власні Y. Чат продовжує працювати (сервер розшифровує й перешифровує
повідомлення та показує відкритий текст), проте відбитки ключів у вкладках перестають збігатися —
звірка відбитків іншим каналом виявляє атаку. У навчальному режимі (Q = 23) ключ підбирається
перебором — він лише для демонстрації обчислень.
