# ЛР №2. Шифрування даних несиметричним алгоритмом RSA

Безпека програм та даних · Мамішев Е. І., ПЗПІ-23-6, варіант 13.

## Структура

| Проєкт | Призначення |
|---|---|
| `Rsa.Core` | Математика та RSA: `NumberTheory` (НСД, розширений Евклід, обернений елемент, модульне піднесення до степеня «квадрат і множення»), `PrimeGenerator` (Міллер–Рабін, генерація простих через `RandomNumberGenerator`), `RsaKeyPair`, `RsaCipher`, `Hex` |
| `Rsa.Web` | ASP.NET Core minimal API + сторінка `wwwroot` (HTML/CSS/JS без CDN); `rsa.js` — власна реалізація RSA на `BigInt` для браузера |
| `Rsa.Tests` | xUnit-тести |

`System.Numerics.BigInteger` використовується лише як контейнер для великих чисел (+, −, ×, ÷, %).
`BigInteger.ModPow` і `System.Security.Cryptography.RSA` у програмі не використовуються (`ModPow` — лише як еталон у тестах).

## Запуск

```
dotnet test Rsa.sln

```

Відкрити http://localhost:5102.

## Інтерфейс

1. **Генерація ключів** — розмір N (512/1024/2048 біт), E (17/257/65537), вивід P, Q, N, φ(N), E, D у hex або dec, перевірка D·E mod φ(N) = 1; покроковий приклад на малих числах (P = 61, Q = 53, E = 17, M = 65 → C = 2790).
2. **Шифрування / розшифрування** — текст → блоки Mᵢ → Cᵢ = Mᵢ^E mod N і назад Mᵢ = Cᵢ^D mod N.
3. **Обмін з сервером** — браузер (а) формує ключі клієнта, (б) отримує `GET /api/server-key`, шифрує повідомлення ключем сервера й надсилає `POST /api/exchange`; сервер розшифровує, формує відповідь і шифрує її відкритим ключем клієнта; браузер розшифровує. Журнал показує, що йде мережею (hex) і що бачить кожна сторона.

## API

| Метод | Опис |
|---|---|
| `POST /api/keys` `{bits, e}` | нова ключова пара |
| `POST /api/demo-small` `{p, q, e, m}` | покроковий приклад на малих числах |
| `POST /api/encrypt` `{text, e, n}` | шифрування тексту (числа — hex) |
| `POST /api/decrypt` `{cipherBlocks, d, n}` | розшифрування |
| `GET /api/server-key` | відкритий ключ сервера (1024 біт, генерується під час запуску) |
| `POST /api/exchange` `{ciphertextBlocks, clientPublicKey:{e, n}}` | обмін повідомленнями |

## Схема блоків

Текст кодується в UTF-8, байти діляться на блоки по **k − 1** байт, де k — довжина N у байтах; кожен блок
читається як число big-endian, тому Mᵢ < N. Під час розшифрування всі блоки, крім останнього, доповнюються
нулями до k − 1 байт (провідні нульові байти останнього блоку можуть загубитися лише для тексту з символом U+0000,
якого в UTF-8 звичайного тексту не буває).

Це «підручниковий» RSA без доповнення: він детермінований і вразливий до низки атак. У реальних системах
використовують схему доповнення OAEP (для шифрування) та PSS (для підпису), а RSA — переважно для обміну
симетричним ключем.
